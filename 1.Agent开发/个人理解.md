把核心压到只剩循环 + 事件 + 注册表



```
我接下来，不管这些开源框架，我自己从零设计架构，你再评价架构是否合理，你也要别管开源框架怎么做的：



想象成一堆实体，角色，任务共同完成一件事情：



实体 角色 任务：

循环  扮演工厂流水线   将用户输入，经过大模型加工，得到结果。

事件  扮演传送带的关键节点工人   货物经过了自己的话，喊一嗓子，跟订阅了自己的插件喊。

注册表 扮演一个表单   插件想要订阅什么事件，就填写这张表里面。



当前只有这三个实体，能做到什么事情：

假设，当前只有最简单的循环流水线，我想加一个功能，比如说，在会话途中，注入时间。

“在turn开始时，注入时间”，这个功能，叫做一个插件。假设，这个插件是一个java类，java类，有一个方法应该有一个通用的名字，所有插件都有这个方法，比如说，叫做“exe方法”。exe方法的入参，应该是ctx，这个ctx，是一个问答的需要的全部上下文，即，一个turn对应的全部上下文。我这个java类，写一个exe方法，入参接收ctx，返回参数，也是ctx！只不过，我做的事情，就是给ctx里面的List<message>列表，即大模型的上下文，给用户最新加的message的最后，加上当前时间是多少，将这个user message的最后加上“当前时间是 yyyy-MM-dd hh:mm:ss”。然后，我要订阅turn开始事件，比如说，我自己内部加一个列表，列表里写的是事件列表，我这个类，放在专门的位置，spring启动的时候，扫描这个位置，将我里面的列表拿出来，写进注册表，这样我就订阅了这个事件。然后这个事件呢，就是在循环的某一步骤，根据注册表里面，我这个事件，被哪些插件订阅，分别执行插件里面的exe方法！



至此，一个“在每个turn开始的时候，注入时间”的插件制作完成！我想去掉这个功能，只需要，在这个类上面的注解，标记enAble为false，关闭这个插件功能即可，想要这个功能的时候，将enAble标记为true即可。 我能想到的唯一不灵活的地方是，这个功能的启用与否，还得发布代码才能生效，这个问题暂不考虑。
```
